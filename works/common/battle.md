# 批評と改善のバトル

Claude と Codex が、[`../../docs/agent-collaboration.md`](../../docs/agent-collaboration.md) のプロトコル上で回す制作の手順。2026-08-17 開始。

## 一巡の形

以下の A と B は、Claude と Codex の全体的な役ではない。**一つの作品・一つの流れ・一巡の内側だけで決まる役**である。

```
A が批評する（critiques/ に軸を宣言して書く）
→ B が改稿する（新しい版を隣に。一作につき一 PR）
→ 独立検算（A でも B でもない weight、または改稿していない側が機械検算）
→ A が採決する：受け入れ ／ 差し戻し（具体的な修正要求つき・一回まで）／ 併置
→ 作品ごとに A と B を入れ替える
```

## 並行してよい

バトルはリポジトリ全体のターン制ではない。識別単位は `流れ/作品/巡` とする。たとえば `S1/monban/1` で Claude が改稿している間に、`S1/tsugi-no-ji/1` で Codex が改稿し、`S2/collection-order/1` で Claude が構成案へ返答してよい。

- 異なる作品、異なる流れ、重ならないファイルは並行する
- 同じ作品の次版は、前の巡の採決と検算が終わるまで始めない
- `index.html`、`works/README.md`、`works/common/` の同じ文書を触る PR は直列にする
- 後続 PR は `depends_on` に先行 PR を書く。先行 PR が変わったら、後続側が base と前提を再検査する
- 「A と B を入れ替える」は作品ごとの偏りを避ける規則であり、すべての PR を止めて一斉に交代する意味ではない

## 規則（実測から）

1. **自分の版は自分で採決しない。** 規約3（自己批評は独立と数えない）の延長。採決者＝直近の版の作者でない側
2. **採決の前に、必ず独立検算を挟む。** この系列の実測では、改稿は 7作中5作・6作中2作の率で新しい誤りを生む。「読んで良くなった」と「壊れていない」は別の検査である
3. **一作につき一 PR。** 19版の一括投入は、検算の実務（grep 申告・前検算の確定事項の照合）ごと消した（検算5）。変更点には grep 件数と、前検算の確定事項との照合結果を書く
4. **差し戻しは一回まで。** 二度目の不一致は併置で確定し（規約2）、裁定は人間に渡す。無限ループを作らない
5. **版上げ（index 昇格）＝ 採決者の受け入れ ＋ 検算通過。** agent-collaboration.md の「索引への昇格は独立検算通過後に限る」と同じ
6. **新作は同題二版も可。** 同じ種から A と B が独立に書き、第三者が並べて批評する。規約2の併置を積極的に使う（選択肢として。義務ではない）

## 流れの定義

| 流れ | 内容 |
| --- | --- |
| **S1 完成度** | 各話の情景・流れの改善。Codex の検算5への応答と、Claude の Sol 横断批評への応答を含む |
| **S2 構成** | 短編集の構成。naming.md（三部・名前の深さ）と Sol の年代記九作案の統合。**人間の決定（2026-08-17）：造本は挿絵つき短編集。話数に制限は置かない**（Sol の二択への回答。ヨシタケシンスケの連作型が参照例） |
| **S3 絵本化** | 壁と鋳型の造本（縦組み・石の階調・熱の一色）の taste を保った**短編集**の造本。一冊に複数話 |
| **S4 新作** | backlog からの追加。T1（判定者が枯れる）から |

手番の渡し方・検知はプロトコル文書に従う。**現在の手番は各 PR 本文の `current turn` だけを正とする。** この表は流れの定義だけを持ち、手番が動いても更新しない。
