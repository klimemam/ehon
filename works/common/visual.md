## 1. 基底として採るもの

[ehon-v1.html](../kabe-to-igata/ehon-v1.html) の造本を共通の基底とする。よく出来ている部分：

| | |
| --- | --- |
| **配色** | 石の階調（`--ground` `--wall` `--wall-2`）＋墨（`--ink`）＋灰（`--ash`）に、**熱の一色だけ**（`--bronze`）。**強い色が一つしかない**のが効いている |
| **縦組み** | `writing-mode: vertical-rl`。860px 以下で横組みに退避する二段構え |
| **明暗両対応** | `prefers-color-scheme` ＋ `data-theme` の二重定義 |
| **描画規則** | `.ink` `.dim` `.ashln` `.hot` の四階調だけで全図版を描いている。**線の意味が色で決まっている** |
| **奥付** | [`README.md`](../README.md) 規約14・15（造本と流通の宣言）が、そのまま紙面になっている |

**熱の一色（`--bronze`）の使い方が、この造本の背骨である。** 鋳型の口、回った水車、食い違った文字——**変化が起きている場所にだけ熱が乗る。** これは意味と結びついた色であって、装飾ではない。

## 2. パワポ感の診断

**症状は三つあり、いちばん重いものは規約違反である。**

### (a) 図版の中に文字がある ── 規約9違反

現行の図版には、SVG 内テキストが入っている。

```
「同じ角度」「十とも、回らない」「世界が、違う返事をした」
「食い違ったまま並ぶ」「これは彫られなかった」「文字は一色になった」
```

**これらは全部、隣の本文に書いてあることの言い換えである。**

[`README.md`](../README.md) 規約9：**語と絵を言い換えにしない**（Nikolajeva & Scott）。図版が本文を復唱している。

**そして、これがパワポに見える最大の原因である。** スライドとは、図の中に結論を書いたものだからである。

**対処**：図版から文字を全部抜く。抜いて意味が伝わらない図は、**図のほうを描き直す。**

### (b) 反復が機械的である

`<use href="#fig">` を等間隔・同一寸法で並べている。

```
x="60" x="96" x="132" x="168" x="204" x="240" x="276" x="312"
```

**複製の主題を、複製の描画で表している。** これも言い換えの一種で、しかも**きれいに揃いすぎている**。

**対処**：間隔と寸法に、決定的（乱数でない）な揺らぎを入れる。**同じ鋳型から出ても、置かれた場所は同じでない。** 揺らぎの入れ方自体が主題に接続する。

### (c) 線に手が無い

`vector-effect: non-scaling-stroke` と `stroke-linecap: round` で、線幅が完全に均一である。円は真円、水車の輻は正確に等分。

**CAD の図面であって、彫った跡ではない。**

**対処**：線幅を一定にしない。とくに `.ink`（彫った線）は、彫りの深さが幅に出るはずである。**深く彫られた文字はよく溶けた**——本文がそう書いているのだから、深さは描かれていなければならない。

**これが (a)(b)(c) のうち最も直接に主題と結びつく。**

## 3. 相ごとの視覚（[`phases.md`](phases.md) 対応）

短編集が進むにつれ、配色と図版の役割が変わる。**現行の石の配色は第III相のものである。** 全編に使うと、相の変化が視覚に出ない。

| 相 | 素材 | 熱の一色 | 図版の役割 | 状態 |
| --- | --- | --- | --- | --- |
| **I　拡張** | 土・木 | 火（暖色） | **道具そのものを描く。** 使う手が必ず画面にある | 未定義 |
| **II　作り変え** | 紙・墨 | 朱 | 人を描く。**道具は画面の端にある** | 未定義 |
| **III　自己生成** | 石・鉄 | 青銅（`--bronze`、現行） | **手が消える。** 図版から人が減る | **定義済み** |
| **IV　希少性** | 水・灰 | 冷たい方へ（未定） | 物と量を描く。**個体が数になる** | 未定義 |
| **V　向かう先** | ？ | ？ | ？ | 未定義 |

### 通す規則（案）

1. **熱の一色は、相ごとに変わるが、常に一色だけである**
2. **図版に文字を置かない**（規約9）
3. **相が進むほど、画面から手が減る。** 第I相では手が必ずある。第III相で消える。**第V相でどうなるかは、まだ決めない**
4. **第V相の視覚を先に決めない。** [`phases.md`](phases.md) §6 が向かう先を四つ並べたまま結論を出していないので、**視覚だけ先に決めると、話のほうが縛られる**

### 第V相について

**決めないことが設計でありうる。** ゴーギャンの画面は、右端の赤子と左端の老女を**同じ一枚に並置**した。順路を選ぶのは鑑賞者である。

第V相の図版を、**前の四相の図版の断片を並置したもの**にする案がある。新しい像を足さずに、既に描いたものの置き直しだけで作る。

**未検討。** [`phases.md`](phases.md) §7 の発表順（II→III→IV→V→I）を採るなら、第V相は最後から二番目に来る。そこで断片を並置すると、**最終編（第I相）へ渡す働き**を持ちうる。

## 4. 保留

- **絵が一枚も無い作品が13ある。** [`README.md`](../README.md) 規約12 は、絵が半分以上でなければ日本の選書制度では絵本でないと宣言している。**造本を持つのは壁と鋳型だけである**
- 図版を人手でなく生成で描くか。現行は手書きSVG。**規約12 の宣言と、生成物であることの宣言が両方要る**
- 判型・見開き数は壁と鋳型でしか決まっていない（規約14）

**いずれも作らないと決まらない。** 第I相の一編を作るときに、同時に相Iの配色を定義するのが順序として正しい。

## 5. 反証：造本試作第二号（2026-08-18）

§4 の「絵が一枚も無い作品が13ある」「造本を持つのは壁と鋳型だけ」は、記録時点では正しかったが、現在の全量を表さない。

[`book-proto-2.html`](book-proto-2.html) は、第一部五話を一つの造本へ流し込み、表紙一・扉五・第一話の場面五、計十一葉の手描きSVGを持つ。図版内の説明文字も〇葉であり、§2(a) への最初の応答になっている。

ただし、これは§4を解決したという反証ではない。

- 場面を絵が運ぶのは『次の字を当てる遊び』だけで、他の四話は扉一葉だけ
- 五話とも `spreads:` の宣言が無い
- `@page` や `@media print`、物理寸法、塗り足しを持たず、レスポンシブWeb試作である
- 第一部は第I相と第II相をまたぐため、現行の石色を全五話へ一律に当てると時系列の差を消す

よって現在地は、「壁と鋳型だけ」から「第一部のWeb造本と一話ぶんの場面絵」へ進んだところである。紙の造本、残る四話の場面絵、相ごとの色は未完のままである。

以後の実測、場面台帳、通過条件は [`collection/picturebook-production.md`](collection/picturebook-production.md) を正本とする。
