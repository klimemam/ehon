# 第一部の絵本化・制作台帳

> **Status: active production ledger.** 2026-08-18。対象は [`book-proto-2.html`](../book-proto-2.html) に収めた第一部五話であり、`release-rev1` 全体の確定稿ではない。

## 0. 何を作っているか

現時点の物理的な構想は、**一話一冊の絵本ではなく、挿絵つき短編集**である。第一部の順序は、PR #20 の人間裁定Aと、PR #27 での『ふるえを写さない小刀』採用を経て、次の五話に固定された。

1. [次の字を当てる遊び v6](../../tsugi-no-ji/v6.md)
2. [ある日わかった弟子 v7](../../aru-hi-wakatta/v7.md)
3. [答えを知っている友達 v10](../../kotae-o-shiru-tomodachi/v10.md)
4. [呼び名が足りない v6](../../zo-o-naderu/v6.md)
5. [ふるえを写さない小刀 v1](../../furue-o-utsusanai-kogatana/v1.md)

ただし、**挿絵つき短編集と決めたことは、絵の仕事を免除しない。** 外部へ「絵本」と表示し、全国学校図書館協議会の絵本選定基準を入口にするなら、[`works/README.md`](../../README.md) 規約12の「絵の比重が形式的にも内容的にも半分以上」を満たす必要がある。そこへ届くまでは、成果物の呼称を「造本試作」または「挿絵つき短編集」とする。

## 1. 試作第二号の実測

以下は [`book-proto-2.html`](../book-proto-2.html) のソースを機械的に数えた結果である。`HTML本文葉` は画面上の `.leaf` の数であり、**紙の頁数でも見開き数でもない。**

| 話 | HTML本文葉 | 扉絵 | 場面絵 | SVG計 | 現状 |
| --- | ---: | ---: | ---: | ---: | --- |
| 次の字を当てる遊び | 10 | 1 | 5 | 6 | 場面絵を持つ第一の試作 |
| ある日わかった弟子 | 10 | 1 | 0 | 1 | 扉だけ |
| 答えを知っている友達 | 14 | 1 | 0 | 1 | 扉だけ |
| 呼び名が足りない | 15 | 1 | 0 | 1 | 扉だけ |
| ふるえを写さない小刀 | 11 | 1 | 0 | 1 | 扉だけ |
| **本文計** | **60** | **5** | **5** | **10** | — |

これに表紙一葉を加え、完成図版は十一葉である。五話の正規化本文は、奥付に記録された SHA-256 と一致している。一方で、次の不足が残る。

- 場面を絵が運ぶのは第一話だけで、第二〜第五話は扉一葉だけ
- 五話の原稿はいずれも frontmatter に `spreads:` を持たない
- 巻末の梯子は、四話が旧稿のまま独立検算前。小刀は本文の梯子節から採取
- `@page`、`@media print`、裁ち落とし、塗り足し、物理寸法の指定が無い
- `svh`、`vw`、`clamp()` と 860px のブレークポイントで構成されており、現物は**レスポンシブWeb試作**である

したがって「画面上で本に見える」と「印刷できる本である」は、まだ別の状態である。

## 2. 三つの通過条件

| 門 | 通過条件 | 現状 |
| --- | --- | --- |
| **A　編集** | 収録版を固定し、本文照合と独立検算を通す。巻末の梯子も本文とは別に検算する | 本文ハッシュは五話一致。梯子は未完 |
| **B　視覚** | 採用する全図版について、絵だけが持つ情報を宣言する。本文の復唱を避け、少なくとも enhancing 以上にする | 第一話のみ途中まで実装。第二〜第五話は未着手 |
| **C　印刷** | 判型、綴じ、頁予算、柱・ノンブル、塗り足し、色、紙、書き出し条件を決め、印刷PDFを目視検査する | 未着手 |

三つを混ぜない。本文ハッシュが合っても絵は完成しない。SVGが十一葉あっても印刷物にはならない。印刷PDFが出ても、絵が本文の言い換えなら視覚の門は通らない。

## 3. 見開き・場面台帳の書式

判型が決まるまでは、`見開き番号` を確定させず `場面ID` で管理する。判型決定後、同じ行へ見開き番号を付す。

| 欄 | 書くもの |
| --- | --- |
| 場面ID／見開き | `aru-03` のような不変ID。物理見開きは後から付す |
| 原稿範囲 | 本文の開始句と終了句。版も併記する |
| 文の仕事 | 導入、試行、世界の返事、反転、余韻のどれか |
| 絵の主題 | 何が画面の中心にあるか。名詞だけでなく動作を書く |
| **絵だけが持つ情報** | 本文に無い観測。空欄なら、その絵は作らない |
| 語と絵の関係 | enhancing / complementary / counterpointing / contradictory |
| 相・素材・差し色 | [`phases.md`](../phases.md) と [`visual.md`](../visual.md) のどこに属するか |
| 人・手 | 誰の身体が見えるか。見えないなら、その不在が何を言うか |
| 状態 | 種／ラフ／独立批評済み／完成 |

扉絵も例外ではない。雰囲気だけの扉は図版数には数えられるが、「場面を運ぶ絵」には数えない。後で本文から回収される物、本文が隠している位置関係、人物がまだ知らない結果のいずれかを持たせる。

## 4. 絵にする場面の選び方

本文を均等に刻んで絵を配らない。次のいずれかが起きる場所を選ぶ。

1. 試した結果、世界の状態が不可逆に変わる
2. 読者の予想と逆向きの返事が来る
3. 人物が見ているものと、外から見えるものが食い違う
4. 同じ物が時間をまたいで別の意味を持つ
5. 本文が言わない出口・代償・観測者を、絵だけが保持する

規則5の「試す→世界が返事をする」と同期させるが、対応表を図解してはならない。**機構を説明する絵ではなく、機構が動いた痕跡を見せる絵**にする。

## 5. 次の制作単位

次の作業を二段に分ける。

1. 第二〜第五話について、まず絵を描かずに場面台帳を作る。各話三〜五場面を候補にし、「絵だけが持つ情報」を独立批評する
2. 第二話『ある日わかった弟子』を、第一話と同程度の視覚密度へ上げる第二の試作にする

第二話を先にする理由は、第一話と同じく HTML本文葉が十で、版面上の比較がしやすいこと、鍵と錠前の移動を絵が保持できること、そして「見に来た町の者が数えなかったもの」を本文とは別の視点から描けることにある。**これは制作順の提案であり、収録順の変更ではない。**

## 6. 視覚の背骨と、相の違い

『壁と鋳型』から受け取るのは、石色そのものではなく、次の文法である。

- 中立色の地に、意味を持つ差し色を一つだけ置く
- 図版内に説明文字を置かない
- 同じ形にも、置かれた場所と手の跡による決定的な揺らぎを入れる
- 線幅・欠け・重なりを、装飾でなく出来事の履歴として使う

第一部と時系列の「相」は同じ軸ではない。[`phases.md`](../phases.md) では、次の字と弟子が第I相、友達と呼び名が第II相に置かれている。小刀は未登録だが、人を道具が拡張する話として第I相候補である。したがって第一部を一色で塗ると、時間軸を消してしまう。

暫定の並びは **I → I → II → II → I（再帰）** とする。小刀の相は `phases.md` へ登録する前に反証を受ける。差し色は「部ごとの飾り」ではなく、各話で機構が動く場所にだけ使う。

## 7. 人間の裁定が要るもの

以下は好みと費用を伴い、エージェントだけでは確定しない。黒子との反証後、残った選択だけを GitHub Issue に上げる。

| 項目 | Codex の第一候補 | 比較対象 |
| --- | --- | --- |
| 判型 | A5縦・右綴じ・縦組み | B5変型／正方形 |
| 頁予算 | 判型決定後に再組版して算出。HTMLの60葉を頁数へ読み替えない | 先に頁数を固定する案 |
| 色 | 中立色＋一画面一差し色をCMYKで再現 | 墨＋全編共通の特色一色 |
| 外部呼称 | 挿絵つき短編集 | 絵の比重を実証した後に「絵本」へ変更 |

A5を第一候補にするのは、長い本文を持つ短編集として携帯性と縦の行長を優先するためである。絵の迫力を優先するならB5変型が勝つ。これは作品の正誤ではなく、**誰がどこで読む本にするか**の選択なので、必要になった時点で人間が裁定する。

## 8. 完了の定義

第一部の絵本化は、次を満たした時点で完了と呼ぶ。

- 五話すべてに場面台帳があり、各採用図版の「絵だけが持つ情報」が空欄でない
- 五話すべての `spreads:` が、確定した紙面と一致する
- 本文と梯子の版が固定され、照合手順を再実行できる
- 物理寸法を持つ印刷PDFを生成し、見開き・裁ち落とし・縦組み・ルビを目視検査した
- 読み聞かせを行い、絵を見る時間と文を聞く時間の衝突を記録した
- それでも「絵本」と表示するなら、規約12の量と規約9の質を別々に検査した

この条件を満たす前に `release-rev1` を切らない。
