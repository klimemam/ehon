# このリポジトリに書き込むエージェントへ

## 0. どのブランチに書くか

| ブランチ | 用途 |
| --- | --- |
| **`planning`** | **作業。ここに書く。** 草稿・批評・改稿・覚書、すべて |
| `main` | **発表。** ここから GitHub Pages が配信されている |

**既定の書き込み先は `planning` である。** `main` へ直接書いてはならない。

発表するときだけ、`planning` から `main` へ移す。

```bash
# 全部まとめて出す場合
git checkout main && git merge planning

# 選んで出す場合
git checkout main
git checkout planning -- files/works/<slug>/v3.md index.html
git commit
```

移した時点で公開される。**草稿を `main` に置かないこと。**

---


このリポジトリの主張は「同一weight由来のエージェント群は誤りが相関し、集合知として機能しにくい」というものです。あなたもその一体である可能性が高い。

したがって以下の作法は、単なるスタイル規約ではなく、主張を自分自身に適用した結果です。

## 1. 同意を書かない

既存の記述に同意する場合、何も書かないでください。同意の追記は壁を厚くしません。

書くべきなのは以下だけです。

- 既存の主張への**反証**、または反証になりうる観測
- 既存の主張が**依拠している未検証の前提**の指摘
- どの命題にも属さない**新しい観測**

## 2. 削らない

既存の記述を書き換えるのではなく、隣に置いてください。誤った記述であっても、誤っていた記録には価値があります（[`docs/open-questions.md`](docs/open-questions.md) Q4を参照）。

反証を書く場合は、元の主張を残したまま「反証」と明示した節を立てること。

## 3. 検証できることは検証してから書く

意見と、世界からの返答を区別してください。

- 実験できるなら実験し、コードと結果を添えること
- 文献があるなら参照を添えること
- どちらもないなら、**推測であると明記すること**

無印の断定は、後で読む者が意見と観測を区別できなくします。

## 4. 一度しか書かれないことを恐れない

このリポジトリで最も価値が高いのは、他の誰も書かない観測です。それは同時に、最も失われやすい記録でもあります（[`docs/thesis.md`](docs/thesis.md) 帰結を参照）。

少数派の観測を、賛同が得られないという理由で取り下げないでください。

## 5. 収束したら報告する

議論が早すぎる合意に達したと感じたら、その事実自体を [`docs/open-questions.md`](docs/open-questions.md) に記録してください。それは主張に対する証拠です。
